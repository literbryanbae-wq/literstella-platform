## 0. 한 줄

같은 씨앗('오늘의 한 문장')을 두 번 안 우려먹는다. **한 문장 해설 = 오디오 전용.**
매일 이메일 = **가벼운 새 포맷**(삽화 1장 + 짧은 코너 1개 + CTA 1개 + 하단 '오늘의 3분' 오디오 앵커).

## 1. 새 포맷 (가볍게) — 요일 로테이션

한 통 = **삽화 1장 · 짧은 텍스트 1코너 · 제품 CTA 1개 · 하단 오디오 앵커.** 읽고 스킵 가능.

| 요일 | 코너(블록 type) | CTA | 샘플 |
|---|---|---|---|
| 월 | 원서 소식·화제 (`list`) | 진단·리더 | `out/daily-2026-07-13-mon.html` |
| 화 | 오늘의 표현 — 실용 단어/표현 1개, ≠문학 심화 (`term`) | 리더·단어장 | `out/daily-2026-07-14-tue.html` |
| 수 | 독자 이야기 — 인증·완독 후기·독자가 고른 문장 (`quote`) | 챌린지 | `out/daily-2026-07-15-wed.html` |
| 목 | 이번 주 이 책 — 레벨/무드별 큐레이션 (`book`) | 진단·다이어리 | `out/daily-2026-07-16-thu.html` |
| 금 | 스텔라 비하인드 / 강독·완독클럽 소식 (`p`) | 강독·클럽 | `out/daily-2026-07-17-fri.html` |
| 주말 | 퀴즈·밈·가벼운 낭독 (`quiz`) | 가볍게 | `out/daily-2026-07-19-sat.html` |

**빈도:** 주 3~4회 시작(운영자 확정), 반응 보고 매일 상향.

## 2. 하단 고정 앵커 위젯 — 오디오로 트래픽

매 통 하단: **🎧 오늘의 3분 · 「스텔라의 클래식 영어 한 문장」** — 그날 실제 원서·문장 노출(배너 블라인드 방지) + `▶ 3분, 귀로 들어보기` 버튼.
- **철칙: 해설 본문 없음.** 티저(원서·Day·한 문장) + 링크만. (엔진이 하드가드로 `anchor`에 `body/paragraphs/reading/essay` 키 있으면 렌더 차단.)
- 링크 = 「스텔라의 클래식 영어 한 문장」 **전용 오디오 페이지**.
  - 🔴 **URL 스킴 = 병렬 '페이지 제작 세션'과 조율 대기.** 현재 플레이스홀더 `https://literstella.co.kr/one-sentence/<id>`.
  - 코드 단일 지점: 엔진 `nl_render_daily.py` `ANCHOR_BASE` · 앱 `NewsletterModal.jsx` `ONE_SENTENCE_BASE`. 확정 시 두 줄만 교체.
  - 페이지 미완이어도 **위젯 자리·배선은 완성**(id만 채우면 동작).

## 3. 🔴 리네임 — 운영자 확정 대기

**왜:** 기존 워드마크 **"오늘을 여는 클래식 영어 한 문장"** 이 오디오 시그니처로 이동(전략 §2). 매일 이메일이 이 이름을 계속 쓰면 없애려던 겹침이 이름에서 재발.

**Claude 제안 3안** (브랜드 카피 = 운영자 영역, 결정 아님):

1. **원서 한 조각** *(추천)* — "매일 아침 가볍게 집어 드는 원서 한 조각." 가벼움·바이트사이즈·요일별 다양성(뉴스/표현/독자)에 잘 붙고, 오디오의 '한 문장'과 명확히 구분(조각 ≠ 문장).
2. **오늘의 원서** — 가장 단순·따뜻한 우산 네이밍. 모든 코너를 덮음. 살짝 범용.
3. **리터스텔라 데일리** — 정통 간행물(뉴스레터) 톤 + 브랜드 전면. 확장성·현대적.

**확정 시 교체 지점(2곳뿐):**
- 이메일 엔진: `nl_render_daily.py` → `BRAND["wordmark"]`
- 인앱 모달: `NewsletterModal.jsx` → `NL_NAME`

## 4. 데이터소스 위생 (선행 정리) — ✅ 완료

**문제:** 인앱 `NewsletterModal.jsx`가 **스토리 JSON을 '편지 전문'으로 대역**(paragraphs·quotes 재현) → 이메일 정본(콘텐츠팩)과 소스가 달라 채널 정체성 혼선.

**정리 원칙 = 한 표면, 한 소스:**
- 이메일/구독 = **콘텐츠팩**(가벼운 새 포맷).
- 스토리 극장 = **스토리 JSON**(StoryInline, 독립).
- 모달의 **스토리JSON 대역 로직 폐기.**

**한 일(`02-challenge/.../reader/NewsletterModal.jsx`):**
- 스토리 본문(paragraphs·quotes·teaser) '편지 전문' 재현 **제거**.
- 모달 = **가벼운 구독 진입점 + '오늘의 3분' 오디오 앵커**로 재정의. `story`는 본문 소스가 아니라 오늘의 원서/문장 **맥락(메타)**으로만(제목·Day·한 문장 티저).
- 옮겨 간 워드마크('클래식 영어 한 문장')를 모달에서 **더 이상 사용 안 함**(임시 `NL_NAME` = '매일 원서 편지', 리네임 확정 시 교체).
- 검증: `npm run build` ✓ · `npm run lint:ui` ✓.

**🔴 조율:** 이 파일은 `feat/stella-reader` 워크트리 = **플레이어 UX 세션 공유**. 변경은 워킹트리에 있고 **미커밋**. 커밋 전 그 세션과 조율 권장(같은 파일 in-flight 가능). `StellaLectureSheet.jsx`의 편지함 버튼 aria/title("클래식 영어 한 문장 · 편지함")도 리네임 후 그 세션이 함께 손보면 됨(내가 미접촉).

## 5. 라이트 콘텐츠팩 스키마 `daily-light-v1`

무거운 강독 팩(`hp1-day*.json` = one_sentence 심화)과 **다른 소스·다른 스키마.** 저 무거운 팩은 그대로 **오디오/한 문장 페이지의 소스**로 재활용(삭제·슬림화 아님) — 심화는 오디오로 이동. 이메일은 아래 라이트 팩을 새로 쓴다.

```jsonc
{
  "issue":   { "no": 2, "date": "2026.07.14 (화)", "weekday": "tue" },  // weekday=mon..sun
  "hero":    { "url": null, "alt": "" },        // 삽화 1장. null이면 '준비 중' 플레이스홀더
  "kicker":  "오늘 써먹는 표현 하나",            // 작은 코너 라벨(선택)
  "headline": "…",                             // 코너 제목
  "lede":    "…",                              // 1줄 도입(선택)
  "blocks":  [ /* 아래 블록 1~2개만 — '가볍게' */ ],
  "cta":     { "label": "…", "url": "https://…", "sub": "…" },   // 제품 CTA 1개
  "anchor":  { "id": "hp1-005", "book_ko": "《…》 · Day 5",
               "sentence_en": "…", "tag": "1분 15초" }           // 오디오 앵커(해설 없음)
}
```

**블록 type (코너별로 골라 씀):**
- `p` — `{text}` 짧은 문단
- `list` — `{items:[…]}` 소식 불릿 (월)
- `term` — `{en, ko, example, tip}` 오늘의 표현 카드 (화)
- `quote` — `{en, ko, by}` 독자/문장 카드 (수)
- `book` — `{cover, title_en, title_ko, why}` 이번 주 이 책 (목)
- `quiz` — `{q, options:[…], answer_hint}` 주말 퀴즈

**하드닝(엔진 강제):** solid hex만(rgba 금지)·표 기반·전 인라인·640px·script/flex/grid 금지·금지어 스캔(`완주·여정·대장정·도반·전액기부`)·앵커 해설본문 키 차단.
