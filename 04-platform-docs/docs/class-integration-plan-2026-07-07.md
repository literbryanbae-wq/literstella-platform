## 0. 한눈 요약 — 4개 결정 + 1개 아키텍처

| # | 질문 | 결정 | 월 비용 |
|---|---|---|---|
| 1 | 클래스 플랫폼 | **LiveKlass 잔류**(단기~중기) + 통합 레이어는 자체 구축. 자체 허브 재검토 트리거 = 연매출 3~5억 or 수수료 인상 통보 | 미디엄 연결제 6.4만 + 매출의 5%+PG 3.5%(+VAT) |

| 4 | 굿즈·디지털 판매 | **하이브리드** — 실물=스마트스토어(+마케팅링크), 디지털·강의·챌린지=자체(포트원) | 추가 고정비 0 |
| ★ | 통합 아키텍처 | **"수강 인증 루프"를 자체로 구축** — LiveKlass에 API가 없으므로(확정), 수강 여부를 Supabase `class_enrollments`로 끌어와 스텔라·할인·번들의 단일 원장으로 | 개발 2~4일 |

**전략 한 줄:** 플랫폼(결제·VOD·LMS)은 빌리고, **고객 관계(계정·데이터·AI·커뮤니티)는 전부 우리 것으로** 가져온다. 통합이란 LiveKlass를 대체하는 게 아니라, LiveKlass를 "결제+영상 전달 모듈"로 격하시키고 나머지를 우리 플라이휠에 접속시키는 것.

**완성될 파이프라인:**
```
진단(무료 퍼널) → 챌린지(습관·포인트) → 강독 클래스(주전환, LiveKlass)
        ↑                                     ↓ 수강 인증 루프(신규 구축)
   AI 리포트 라우팅                Supabase class_enrollments (수강 원장)
        ↑                                     ↓
  뉴스레터(쿠션, 스티비) ← 번들 ←  스텔라(AI 심화)·수강할인·쿠폰검증·전용레터
        +  굿즈(크로스셀: 실물=스마트스토어/서점, 디지털=자체 포트원)
```

## 1. 현재 상태와 문제 정의

- **클래스**: 클래식 강독 6종을 LiveKlass에서 판매(6.9만~19.8만원). HP완독클럽 = 네이버 카페 + **YouTube unlisted 링크**(보안 구멍: 링크 유출 시 회수 불가) + 결제는 스마트스토어. 영상 자산 ~800개·~100GB.
- **접점(코드 실측)**: class.literstella.co.kr 링크가 양 앱+워커에 **33곳 하드코딩**(그중 liveklass 고유경로 `cu/` 등 10곳 + SEO 책 페이지 118권 공통 푸터). 에디션 데이터는 진단/챌린지 수동 동기화 복제본.
- **결손(코드 실측)**: 업셀 깔때기(AI 라우팅→강독, YANAWAN 쿠폰 tease→reveal, 100일/완독 이메일 업셀)는 완성돼 있으나, **전환 결과(수강 여부)가 앱으로 돌아오는 경로가 0줄**. 텔라 '스텔라'는 라벨·마스코트만 있고 수강 인증 게이트 코드가 전무. pricing.js의 수강할인권도 검증 소스가 없어 미가동.
- **결론**: 병목은 플랫폼 선택이 아니라 **"수강 인증 루프의 부재"**. 이것부터 뚫으면 기존 자산(텔라·포인트·쿠폰·이메일)이 전부 살아난다.

## 2. 결정 ① 플랫폼: LiveKlass 잔류 + 통합 레이어 자체 구축

### 근거 (리서치 실측)
- **요금**: 무료 플랜 = 수수료 10%·수강신청 20건/월·20GB. 유료(마이크로 1.6만~라지 16만) = 수수료 5%. **영상 100GB이므로 미디엄(200GB, 월 8만·연결제 6.4만) 필요.** 월 매출 100만원만 넘어도 유료 플랜이 산술적으로 무조건 이득(5%p 절약 > 구독료).
- **월 매출 500만 가정 총비용**: 판매수수료 5.5% + PG 3.85% + 플랜 = **월 ~53만원(매출의 10.6%)**. 올인원(한국 결제+VOD+LMS+구독) 대가로 수용 범위.
- **대안 부재**: 아임웹은 API는 있으나 VOD·진도율 없음(강의 플랫폼 결격), Teachable은 국내 PG 미지원. **자체 구축은 연매출 3~5억 도달 후 재검토가 합리적**(그 시점 LiveKlass 수수료 연 5,600만~6,600만원 → 재산정 가치 발생).
- **공개 API/웹훅 없음(확정)**: 외부 연동은 GA/픽셀 수준. SSO도 불가(이중 계정 유지). 수강생 **엑셀 다운로드는 공식 지원**.
- **운영사(퓨쳐스콜레)**: 시리즈A 40억, 거래액 2023 76억→2025 482억. 단기 폐업 리스크 낮음. 단 USD 수수료 인상 전례(6.5→7.0%) = 정책변경 리스크 실재.

### 락인 통제 원칙 (지금부터 상시)
1. 영상 원본 100GB **오프플랫폼 백업 유지**(구글드라이브 등 — 유일한 회수 불가 자산 방지).
2. 수강생 엑셀 **월 1회 정기 다운로드**(고객 DB 자산화 — 단, Supabase 업로드는 §6의 pull 방식만).
3. 커뮤니티·후기·학습데이터는 LiveKlass가 아닌 **자체 앱/카페에 축적**(LiveKlass 커뮤니티 기능 사용 최소화 — export 불가 자산 만들지 않기).
4. **class-links 단일소스 모듈**: 33곳 하드코딩을 양 앱 공유 데이터 모듈(+워커 리다이렉트 `go.literstella.co.kr/class/*` 또는 기존 워커 경유)로 승격 → 훗날 exit 비용을 "모듈 1곳 수정"으로 캡.

## 3. 결정 ② 동영상: Vimeo Standard ($25/월 연결제)

### "비메오가 최적인가?" → LiveKlass를 계속 쓰는 한 **예** (운영자 직감 검증)
- **LiveKlass는 외부 영상을 YouTube·Vimeo만 수용**하며, 진도(100% 시청 요건)·배속·수강기간 제한이 유지되는 건 **직접 업로드 + Vimeo 타입뿐**. Cloudflare Stream/Mux는 아예 못 붙임 → 외부 호스팅 선택지는 Vimeo 단수.
- **플랜**: Starter($12)는 100GB가 정확히 한도라 여유 없음 → **Standard($25/월 연결제, 2TB 저장·좌석 5)**. 2024-06 이후 신규 계정은 영상 개수 제한 없는 누적 GB 저장제 → 800개 업로드 문제없음.
- **스크립트 API(운영자 핵심 요구) 확인됨**: AI 자동 자막 한국어 지원(유료 전 플랜) + `GET /videos/{id}/texttracks`로 **transcript 추출 공식 지원** → 800개 강의 스크립트를 텔라 AI(스텔라)·검색·SEO 자산으로 재활용 가능. ⚠️ 단 이 2차 활용은 **강사 IP 서면합의가 선행 게이트**(§8-6).
- **권한 설정(운영자 핵심 요구) 확인됨**: 도메인 임베드 제한 + 비공개 링크 + 다운로드 차단. **HP완독클럽의 YouTube unlisted를 즉시 대체** — 현재 최대 보안 구멍을 월 $25에 해소.
- ⚠️ **한국 재생 품질 전례**: 인프런이 버퍼링으로 이탈한 사례(2020) 있음. 2026 현재 상태 미확인.

### 게이트: 파일럿 10개 (전량 이전 전 필수)
영상 10개만 Vimeo에 올려 ① LiveKlass 임베드+진도율(100% 시청)·배속 실동작 ② 모바일 재생 ③ **한국 피크타임(21~23시) 재생 품질** ④ 도메인 제한 작동 — 전부 통과 후에만 800개 이전. 실패 시 LiveKlass 직접 업로드 유지(미디엄 200GB로 수용 가능).

### 자체 허브 전환 시(Phase 3+)에는 Cloudflare Stream
저장 $5/1,000분 + 전송 $1/1,000분 ≈ 월 $110(시청 1,000시간 가정). Workers 바인딩으로 signed URL 발급 → Supabase 세션 결합이 수십 줄. 한국어 AI 자막 무료 + Captions API. 기존 스택이라 벤더 추가 0. (Mux가 ~$50로 더 싸지만 자동자막 한국어 미확인 + 벤더 추가 — 비권장.)

## 4. 결정 ③ 뉴스레터: 스티비 유지 + Resend 역할분담 공식화

### "Resend로 전환?" → **아니오. 전환이 아니라 이원화 공식화가 정답**
- **비용 역전 없음**: 일간 발행(구독자×30통/월)은 구독자 기준 과금이 유리. 스티비 스탠다드가 전 구간 최저가 또는 동급 — 1,000명 1.6만 / 5,000명 3.9만 / 20,000명 9.9만원(발송 무제한). Resend Marketing은 5,000콘택트 $40≈5.6만 + **세그먼트·구독폼·아카이브·유료구독이 없어** 전부 자체 개발해야 함(1인 운영 비합리). 메일리는 발송 건수 과금이라 일간 발행에 3~7배 비쌈. Beehiiv/Buttondown은 유료구독 결제가 **Stripe 전용인데 한국 미지원** → 탈락.
- **도달성**: 일간 뉴스레터가 스팸함에 가면 상품 자체가 죽는다. 스티비=국내 발송 인프라+네이버/다음 도달 노하우가 핵심 상품가치. Resend(AWS 해외 인프라)로 일간 수천 통 마케팅 발송은 미검증 리스크.
- **역할 분담(업계 표준 패턴)**:
  - **스티비** = 콘텐츠·대량발송 축: "오늘을 여는 한 문장"(일간)·유료 뉴스레터·공지. 운영자가 에디터에서 직접 작성.
  - **Resend+Worker** = 트리거·개인화 축(현행 유지): OTP·문의·마일스톤·수강생 전용 개인화. **마케팅성 메일을 Resend(noreply@)로 보내지 말 것** — 도메인 평판 분리가 이 구조의 이점. 스티비 발신자는 별도 주소(letter@) 권장.

### 유료 뉴스레터 = 즉시 실행 가능한 신규 수익
- **스티비 유료 구독**: 월 1,000~100,000원 설정, 정기 자동결제, **플랫폼 수수료 0% + PG 3.2%만**, 익월 25일 정산. 개발 0으로 저가 구독(월 4,900~9,900원) 리드 상품 → 강독 퍼널 상단 확보.
- **수강생 번들**: 강독 구매자를 스티비 비공개 주소록에 등록(수강 인증 루프 §6과 연동) → "강독 수강생만 받는 편지" = 클래스 전환 인센티브.
- ⚠️ **"호그와트 영어 편지" 리네이밍 필요**(§8-1 — 유료 상품명에 HP 상표 사용 금지).

### 개발 항목 (1~2일)
- 가입/옵트인 시 Worker→스티비 **구독자 API v2** 등록(닉네임·레벨·수강 여부 커스텀 필드 포함 → 세그먼트 활용).
- 수신거부 정본=스티비. Worker cron으로 주기 폴링해 Supabase `newsletter_opt_in` 역동기화(웹훅 미확인이라 폴링 전제) — **스티비에서 수신거부한 사람에게 Resend 라이프사이클 메일이 계속 나가는 구멍 방지**(§8-9).

## 5. 결정 ④ 커머스: 축은 "실물 vs 디지털"이 아니라 "발견 vs 관계"

### 수수료 실측 (영세 등급 = 연매출 3억 미만, 3만원 상품 1건)

| 채널 | 실효 수수료 | 실수령액 |
|---|---|---|
| 스마트스토어 (일반 노출 구매) | 주문관리 1.947% + 판매수수료 3% = **4.947%** | 28,516원 |
| 스마트스토어 (**마케팅링크** 유입) | 1.947% + **1%** = 2.947% | 29,116원 |
| 자체 포트원+이니시스 카드 | **1.76%**(영세 공시 예시, VAT 포함 환산; 포트원 월 거래 5천만 이하 무료) | 29,472원 |

- 2025-06 개편으로 판매수수료는 **유입 경로 무관 전 판매 3% 부과**(구 "네이버쇼핑 유입 시만 2%"는 폐지). 외부 채널(앱·카페·유튜브·블로그) 유입은 **"마케팅링크" 생성 시 1%**.
- 스마트스토어는 **구매자 이메일을 판매자에게 주지 않음** → 재접촉 수단 사실상 없음. 자체 채널은 이메일·구매이력·진단·챌린지가 한 계정(Supabase+SSO)에 통합 → **디지털 구매자 1명 = 강독(6.9만~19.8만) 전환 후보**라는 점에서 데이터 소유 가치가 수수료 차익보다 큼.

### 권고안 (실행 순서)
1. **지금(무료 개선)**: 앱·카페·유튜브→스마트스토어 링크 전부 **마케팅링크로 교체** → 즉시 판매수수료 3%→1%.
2. **이니시스 실가맹 승인 직후**: 챌린지 참가비(코드 완성) → PDF/전자책 → **HP완독클럽 결제 자체 이전**(디지털이라 배송 無 + 접근권한을 자체 계정과 묶음) 순으로 이전. 자체몰 결제수단은 **카드 우선**(이니시스 경유 네이버페이는 3.63~3.85%로 이점 상실, 초기 미탑재 가능. 카드-only면 현금영수증 의무도 자동 해결).
3. **실물은 스마트스토어 존치**(배송 관리 내장 + 네이버쇼핑 발견 트래픽 — 국내 이커머스 ~20.7~25% 점유 관문). **자체 배송 시스템 구축 금지**(월 100건 수동 배송 = 1인 운영자 주당 수 시간 손실).
4. 스마트스토어 구매자에게는 동봉물·상품 안내로 자체 가입(+포인트) 유도 → 발견 채널에서 관계 채널로 회수.

## 6. ★ 통합 아키텍처: 수강 인증 루프 (신규 구축 — 이 기획의 심장)

LiveKlass에 API가 없으므로(확정), 수강 사실을 앱으로 가져오는 유일한 안전 경로는 **본인 주도(pull) 인증**이다.

### 설계
```
[Supabase] class_enrollments
  user_id · email · product_code(강독6종/HP클럽/번들) · source(liveklass/self/smartstore)
  verified_by(self+admin/auto) · verified_at · expires_at(평생소장=null)
```
1. **수강생 본인 인증(pull)**: 챌린지 앱 마이페이지 "수강 인증" → LiveKlass 구매내역 캡처 제출(기존 카페 인증·관리자 패널 패턴 재사용) → 운영자가 **수강생 엑셀과 대조 후 승인**(AdminPanel 탭 추가).
2. 🚫 **운영자 push 배치 업로드 금지**: LiveKlass에서 수집된 개인정보를 동의 없이 타 서비스 DB로 이전·결합하는 것은 개인정보 목적외 이용(§8-4). 대조용 열람만 하고, DB 기록은 본인이 요청한 건만.
3. **자체 결제 상품(Phase 1+)은 자동**: 포트원 웹훅 → `class_enrollments` 직행(이미 구현된 05-secure-api 레일).

### 이 원장 하나가 켜는 것들 (전부 기존 코드가 대기 중)
| 소비처 | 현재 상태 | 연결 후 |
|---|---|---|
| 텔라 **스텔라** 단계 | 라벨·마스코트만, 게이트 0줄 | 수강 인증 시 스텔라 모드 해금 — 유료 AI 차별화 첫 가동 |
| pricing.js 수강할인권(cap 30%) | 검증 소스 없어 미가동 | 포인트→수강할인 실차감 |
| YANAWAN 쿠폰 | 소진 추적 불가(플랫폼 측) | 사용 추적·개인화 오퍼 |
| 수강생 전용 뉴스레터 | 불가 | 스티비 비공개 주소록 자동 등록 |
| 100일/완독 이메일 업셀 | 맹목 발송 | 이미 수강한 사람 제외(정확도↑) |
| AI 리포트 라우팅 | 전환 결과 미상 | 전환 측정 가능 — "강독 전환율 회복"(2026 최우선)이 드디어 계측됨 |

## 7. 상품·상세페이지 전략 (경쟁사 벤치마크)

### 채택할 패턴 (근거: 클래스유·클래스101·탈잉 실측)
1. **챌린지 동봉형 강의 상품** (탈잉 — 챌린지형 완강률 60%+ vs 일반 VOD ~30%, 2025 매출 +46% 동력): 강독 = "강의 + 야나완 100일 챌린지 자동 등록" 번들. **탈잉이 새로 만든 것을 우리는 이미 보유 — 붙이기만 하면 됨.**
2. **미션 인증 → 포인트 적립 루프** (클래스유 — 결제액 10%를 미션당 분할 지급): 강독 수강 중 인증 1회당 포인트 적립. 기존 포인트 원장(멱등 적립) 그대로 연결.
3. **행동 증거를 사회적 증거로** (클래스유 "미션 완료 64,215개"): 상세페이지에 "누적 인증 N건"(check_ins 실데이터) — **경쟁사는 못 하는 우리만의 실데이터.**
4. **월 환산가 표기**: 19.8만원 강독 → "100일 기준 월 6.6만원".
5. **상세페이지 IA 표준 순서**(3사 공통): 지표 라인 → 가격 → CTA → 커리큘럼 → 후기 → 강사 → 환불정책 → CTA 재반복.
6. **기수제 + 시즌 앵커 동기화**: 강독 기수 오픈을 야나완 시즌(7·11·3월)과 맞춤. 희소성은 할인 사기극이 아니라 **기수 마감**으로.
7. **강의+실물 번들 환불 조항** (탈잉 표준): "배송완료 후 7일 + 미재생 전액, 훼손 시 거절" 구조를 에디션 동봉 상품 약관에 이식.
8. **HP완독클럽 → 기수제 클럽 승격** (클래스101 마스터 모델): VOD+커뮤니티+챌린지 조합 상품.

### 피할 안티패턴
1. **구독 올인 전환 금지** (클래스101 — 크리에이터 이탈·정산 9개월 논란·축소 흑자): 우리 규모에서 구독은 콘텐츠 멤버십 보조까지만, 강독 본체는 단건·기수제.
2. **상시 초할인(71~83%) 금지**: 실판매 이력 없는 부풀린 정가 = 표시광고법 리스크 + 신뢰 브랜드 훼손. 정가는 실판매 이력 가격만.
3. **비현실적 100% 환급 금지** (클래스유 사례): 환급을 걸려면 "미션당 포인트"처럼 작고 확실하게.

## 8. 법·규제·리스크 게이트 (크리틱 12건 — 각 Phase의 선행조건)

1. **HP 상표·저작권**: 유료 상품명·마케팅에 "호그와트" 등 HP 고유명사 사용 금지 → 자체 브랜드로 리네이밍(예: "클래식 영어 편지" 시리즈). HP 관련은 '가이드/스터디' 포지션 유지(기존 본문 0%·강의 100% 원칙의 브랜딩 확장).
2. **디지털 청약철회**: "제공 개시 시 철회 제한"이 유효하려면 **사전 고지 + 별도 동의(체크박스) + 시험시청 제공** 3요건 필수. 자체 결제 플로우 DoD에 포함. 환불 표준 = "7일 + 3강 이하(또는 미재생) 전액"(클래스101·탈잉 표준, 이니시스 심사 대비 약관 선반영).
3. **인허가 확인**: 자체 강의 판매 전 원격평생교육시설 신고 대상 여부 확인(교육청) + 자체몰 푸터 법정 표시 7종.
4. **개인정보 목적외 이용 방지**: §6의 pull-only 원칙. + **RLS 재잠금이 수강 원장 구축의 선행조건**(현재 DEV 해제 상태 — PII 노출 시기와 겹치면 안 됨).
5. **기존 수강생 무손실 승계**: "평생소장"은 계약 — 어떤 전환에서도 재결제 없음, 이전 완료율 95% 전까지 구 채널 병행 유지. 소셜 로그인 이메일 ≠ 실이메일 매칭 실패 대비 수동 확인 절차.
6. **강사 IP 서면합의(최우선, 기존 대기 항목)**: 스크립트 추출·AI 학습(스텔라)·클립 재활용·뉴스레터 인용 등 **2차 활용 조항 포함** — Vimeo transcript 파이프라인과 텔라 연동의 게이트.
7. **Vimeo 파일럿 게이트**: §3 — 임베드·진도·한국 재생 실검증 전 전량 이전 금지.
8. **세무·현금흐름**: 강의·PDF=부가세 과세. 채널 합산 연매출 3억 근접 시 영세등급 이탈 → 수수료 재계산 알림. 정산 지연 겹침 주의(LiveKlass 익월 10일 + 스티비 익월 25일 + 스마트스토어 구매확정 기준).
9. **수신동의 이원화**: Resend=트랜잭션(광고 아님) / 스티비=마케팅(광고) 엄격 분리 + 수신거부 폴링 동기화(§4).
10. **1인 제작 캐파**: 일간 레터 365회+영상+CS를 혼자 감당 — 배치 제작·재활용 규칙(챌린지 인증 데이터→레터 소재화) 필요. 파이프라인보다 노동량이 병목.
11. **가격 표시**: §7 안티패턴 2 — 돈 카피는 운영자 컨펌 원칙 유지.
12. **Exit 비용 캡**: class-links 단일소스 모듈(§2) — 통합 착수 전 선행 기술과제. exit 체크리스트 = 영상 원본(백업 유지로 해결)·수강생 명단(엑셀)·커뮤니티(자체 축적으로 회피)·링크 33곳(모듈 1곳).

## 15. (v5, 2026-07-09) 오디오 = 추출 vs 클론 · 사전생성 vs 실시간 · 상용 vs 자체서버 (결정 확정)

### 🎯 핵심 판단 — 타 제안서가 놓친 것: "이미 녹음된 강의를 왜 다시 합성하나"
타 제안서는 모든 오디오를 **클론 TTS 합성**으로 가정 → 있는 자산(강사 실낭독 800강)까지 가짜로 재생성하는 과오. 정답은 **하이브리드**:
| 콘텐츠 | 처리 | 클론 필요? | 비용 |
|---|---|---|---|
| **기존 6종 800강**(강사 육성 有) | **오디오 추출→R2**(ffmpeg `-vn`) | ❌ | 합성 0(추출=CPU 1회 배치) |
| **신규 원서 강독**(녹음 없음) | 신규 녹음 or 클론 TTS | ⭕ | 합성비 |
| **오답 피드백·임의 문장**(동적) | 온디맨드+텍스트해시 캐시 | ⭕ | 합성비(캐시 히트분 절감) |
→ 진짜 목소리 > 합성. 브랜드(강사 IP)·품질·비용·리스크 전부 추출이 우위. 클론은 녹음이 **존재하지 않는** 신규·동적 콘텐츠에만.

### 운영자 질문 직답: MP3 추출 = 유리 (영상 음성 듣기로는 목표 미달)
운영자 목표(팟캐스트·다운로드·백그라운드)는 **영상 재생으로 구조적으로 불가**: 백그라운드(모바일 웹 화면잠금 시 중단)·잠금화면 제어·오프라인·팟캐스트 RSS enclosure·데이터(영상 수십MB/분 vs MP3 ~1MB/분)·접근성 — 전부 MP3에서만/훨씬 쉽게 충족. **단 MP3 추출 ≠ 클론**(있는 오디오를 뽑는 것). 영상은 영상대로 리더에 두고(보고싶은 사람), 오디오는 추출해 팟캐스트/다운로드 표면을 여는 이중 표면.

### Vimeo 오디오 추출 실무
- Vimeo API는 오디오 전용 파일 미제공 → **영상 파일 다운로드(`GET /videos/{id}?fields=download`, `video_files` 스코프, Standard 이상 플랜·source 저장 활성) → ffmpeg 오디오 추출**. 다운로드 링크는 만료형(배치 시 매번 재조회). 2016.9 이전 API-pull 원본은 다운로드 불가(계정별 확인).
- ffmpeg는 **Cloudflare Workers 불가**(isolate) → **로컬 PC 1회 배치**(800강 수 시간, API비 0). 상시화 시 Cloudflare Containers.
- 음질: 강의 육성이라 128k 충분/192k 안전. **유일 변수=본문 구간 BGM** → 샘플 2~3편 먼저 추출·청취로 확인(강독형은 대개 무). BGM 있으면 Demucs 음원분리.

### 사전생성 vs 실시간 = 사전생성+캐시 압도
- 고정 콘텐츠(강독·뉴스레터·팟캐스트) = **1회 사전생성→R2 캐시**. 실시간 합성은 재생마다 재과금=자릿수 낭비(20분 에피 사전생성 1회 $3~6 vs 월 5,000재생 실시간 $15,000~30,000). R2 egress 무료라 스트리밍 대역폭 0.
- 온디맨드+텍스트해시 캐시 = **오답 피드백·리더 임의 문장**만(기존 AI예문 3겹 캐시 패턴 재사용).

### 상용 vs 자체 GPU = 상용(ElevenLabs) 고정
- 자체 GPU "$3/월 컴퓨트"는 함정: 초기 30~60h + 월 3~6h ML옵스(1인 비개발 병목=시간). 손익분기=월 비캐시 400만~660만 자(오디오 60~110h/일 4~6편 신규) — **현재(월 ~30만 자)의 1/20, 도달 불가.**
- **라이선스 함정**: XTTS v2(CPML)·F5-TTS(CC-BY-NC)=**비상업 금지**, Coqui 2024-01 폐업(상업 라이선스 구매처 소멸). 합법 자체구축은 Chatterbox(MIT)/Piper뿐. 온디바이스(ONNX/TFLite)=React 웹 스택에 비현실·불필요(다운로드는 서버 1회 합성 MP3로 이미 해결).
- **벤더 독립성의 진짜 해독제 = GPU 서버가 아니라 "강사 원본 음성 데이터셋 보관" + 코드에 `ttsProvider` 추상화 1겹.** 원본만 있으면 어느 엔진으로도 재클론.
- **Demucs/WhisperX Forced Alignment = 자체 파인튜닝 데이터셋 구축 요건이지 ElevenLabs PVC엔 불필요**(30분~3h 클린 오디오 통째 업로드). 단 WhisperX 정렬은 **기존 오디오↔JSON 텍스트 시간동기(영어 낭독 구간 컷·리더 카라오케·자막)** 용도로는 이 프로젝트에 독립적으로 유용.

### 교차언어(영어 원문 낭독) 처리
- 클론은 학습 샘플 언어의 억양을 목표언어에 전이(accent leakage) → 한국어 화자 클론이 영어 읽으면 한국어 억양 잔존. **BUT 기존 강의는 강사가 영어를 직접 낭독=추출로 해결(억양 문제 자체 없음).** 신규 영어 낭독은 (a)강사 영어샘플로 학습한 클론 or (b)별도 원어민 보이스(이중언어 오디오북 표준) — **강사 영어 발음 원어민급 여부는 운영자 청취 판단(미확인).**

### 실행 경로(확정)
1. 기존 800강 → 로컬 ffmpeg 추출 → R2(합성 0). 2. 강사 클론 1개 = ElevenLabs PVC(Creator $22, 한/영 각 30분+ 클린) → 신규·동적용. 3. 영어 원문 신규 = 원어민 보이스 or 강사영어클론(청취 판단). 4. 고정 전량 사전생성→R2. 5. 오답·임의문장 온디맨드+해시캐시. 6. 자체 GPU·온디바이스·XTTS/F5 배제. 7. `ttsProvider` 추상화 + 원본 음성 데이터셋 보관.

## 13. (v3, 2026-07-09) 스텔라 모드 MVP — 원서 리더에 강의 통합 + 다른 원서 강독

> 운영자 방향 전환: "회원 연결 스키마 말고, 원서 리더에 VOD 강의 넣고 텔라 스텔라 모드 학습 MVP 먼저. 스크린리더·팟캐스트 포함. 다른 원서를 스텔라식으로 어떻게 강독할지 UX 정의. 새 브랜치로 챌린지앱과 연결?"
> UX 프로토타입(실제 강의 데이터): claude.ai Artifact "스텔라 강독 모드"(favicon ✦📖). 소스 = scratchpad/stella-mode-proto.html.

### 확보된 데이터 자산 (2026-07-09 운영자 제공, 검증 완료)
- **docx** `리터스텔라 원서 유튜브 강의 원문과 스크립트` = 6종 전체 강의 원본(17,282문단·600만자). 구조=책→OT→N강 원문 + N강 강의 스크립트. 키다리 60강·셜록 92강 등 합 ~800강. = **RAG 코퍼스 원천.**
- **JSON** `literstella_full_ai_analysis_dataset.json` = docx 정제 **목표 스키마 샘플**(2종·13청크). 청크=`{lecture_id, lecture_title, text_coverage("Page 1-3"), raw_text_en, raw_transcript_ko, linguistic_nodes[{target,category,definition}]}`. category=Idiom/Grammar/Vocabulary/Cultural Context/Morphology/Characterization/Chemistry Term/Sherlockian Core 등. = **리더 UI 렌더 계약 + AI 출력 스키마.**
- **키다리 xlsx** 수강생목록 = 1,930명 × 82열. **전체진도율·vod수료율 + 강의별 완료(#1~#60, 헤더 "(p.1-3)" 페이지 매핑 + 타임스탬프·%) + 디자이너 워크북 구매자 컬럼.** → 진도율→완독배지, **페이지↔강의 매핑이 데이터에 이미 존재.**
- **마케팅 3천명 xls** = OLE 구형 .xls(회원연결용, 후순위).

### 핵심 설계 결정
1. **소장 6종 = 강사 실제 강의(생성 아님, 할루시네이션 0)**: 리더 페이지 ↔ 강의 청크 결정적 매핑(text_coverage) → 그 페이지 실제 강의 스크립트/영상 표시. RAG·벡터DB 불필요.
2. **그 외 원서 = 스텔라식(式) 생성 강독**: 강사 방식만 학습(도입→원문→핵심 짚기→인물·주제→격려 순서·어투 + linguistic_nodes 분해틀)한 AI가 새 책 문단에 **같은 스키마로** 출력. RAG=~800강 스크립트에서 스타일 예시 검색→Claude(AI Gateway) 생성. **정직 고지 필수**("스텔라식·해석 차이 있음"). = 범용 AI가 복제 못 하는 강사 IP 해자.
3. **하나의 강독 객체 → 3표면**: 읽기(텍스트)·팟캐스트(ttsPlayer 순차+MediaSession)·영상(소장 6종만 Vimeo). 스크린리더=팟캐스트와 같은 순차 낭독+ARIA. **접근성=오디오 우선 강독의 부산물(별도 기능 아님).**
4. **진도율 90%↑ → 완독 배지 자동**(배지만, 포인트 X). 데이터에 진도율 있음 확인.

### 🔑 아키텍처 결정 — 새 앱 아님, **챌린지 레포의 피처 브랜치**
운영자 질문 "새 브랜치? 챌린지앱 연결?" → **`literstella-challenge` 레포 피처 브랜치(`feat/stella-reader`), 별도 앱/레포 아님.**
- 근거: ReaderView·ReadingMate(텔라)·ttsPlayer(전역듣기)·vocab·SSO·Supabase·AI Gateway가 **전부 이미 챌린지 앱에 있음.** 스텔라 모드=이 모듈 재조합. 별도 앱=전부 중복 → architecture_drift.
- "앱이 커지는" 문제 = 별도 앱이 아니라 **코드 스플리팅(lazy import)**로 해결(스텔라/VOD 모듈 동적 로드).
- "챌린지앱과 연결"=모듈로 넣으면 본질적으로 연결. 강의 콘텐츠(Vimeo·스크립트 RAG)=데이터/서비스 레이어지 새 프론트엔드 아님.

### MVP 범위·구축 순서
- **Step A(데이터 파이프)**: docx→JSON 스키마 정규화(6종·~800강). 결정 무관 순수 데이터 → 지금 착수 가능.
